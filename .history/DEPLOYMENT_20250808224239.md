# Deployment Strategy
*Created by Rachel Belokopytov*

This document outlines an initial approach for deploying this full-stack application to production in a way that supports scalability, performance, and reliability.
The system is designed for an estimated 10,000 daily active users and includes both a client-side (React) and server-side (Spring Boot) application.

**Note:** This is more of a first-draft brainstorming plan than a final production-ready strategy.
I’m still learning and exploring the different frameworks, CI/CD tools, cloud services, and load-handling options out there.
I also know there are existing tools and services that can make this easier — for example:

- AWS ECS / EKS for container orchestration
- GitHub Actions / Jenkins for CI/CD

As I gain more hands-on experience, I’ll refine and improve these choices.
The main idea here is simply how I would start approaching deployment.

---

## Executive Summary

- **Containerized Deployment** – Package backend in Docker and deploy to the cloud with auto-scaling and load balancing.
- **Cloud-Hosted Frontend** – Build React app, host via CDN for global access, and integrate with backend APIs.
- **Reliable Database** – Migrate from H2 to PostgreSQL on Amazon RDS with backups and indexing.
- **Performance & Security** – Use caching, JWT authentication, role-based access, and HTTPS for secure, fast service.

## 1. Overview

- Backend: Spring Boot application using REST APIs
- Frontend: React single-page application
- Authentication: AWS Cognito for secure identity management
- Database: Currently H2 (file-based) — planned migration to PostgreSQL

---

## 2. Current Limitations

Before deploying the current version, there are a few challenges to solve:

- Single Spring Boot instance with embedded H2 DB
  - Not scalable or fault-tolerant
  - Can’t handle high concurrency well
  - Risk of data loss or corruption
- No load balancing
  - If 10k users hit the same endpoint at once, it will slow down or fail
- No caching
  - Every request (e.g., GET /users/me) goes directly to the DB, which can slow things down
- No CI/CD pipeline
  - Deployments are manual — not sustainable for production

---

## 3. Proposed Deployment Approach

### Backend (Spring Boot)
- Package the app in Docker, so it can run anywhere with everything it needs inside
- Deploy it to the cloud without having to manage servers manually
- If a lot of people are using the app, run more copies (scale out); if traffic drops, scale back down
- Spread incoming requests across all running instances so no single one gets overloaded

### Frontend (React)
- Build the app using `npm run build`
- Store the built files in cloud storage (e.g., AWS S3) so they load fast from anywhere
- Use a CDN to deliver it globally and connect it to the backend correctly

### Database
- Move to PostgreSQL on Amazon RDS for reliable, persistent storage
- Add indexing and proper normalization for performance
- Schedule daily backups and set up recovery points

### Load Balancer
- Handle incoming requests and route them evenly
- Automatically reroute traffic if a server fails

### Caching
- Cache common queries like user info and project/task lists
- Reduce DB load and make API responses faster, improving the user experience

### Security & Authentication
- Validate JWT tokens for every request
- Keep sensitive data (DB passwords, secrets) secure in environment variables or AWS Secrets Manager
- Use role-based access control so different user types have different permissions
- Configure CORS for safe cross-origin requests
- Use HTTPS for all communication

## 4. Frontend Design Flow

The frontend will follow a login-first workflow:

1. **Sign-In Page** – Users log in via AWS Cognito’s hosted UI or custom sign-in component.
2. **Projects Page (Paginated)** – After successful login, users are redirected to their list of projects.
   - Pagination will be implemented to handle large project lists efficiently.
   - Each project card will provide quick access to related tasks and actions.
3. **Task View** – Clicking a project opens its tasks, which can also be paginated if necessary.

This flow ensures the app loads quickly, remains user-friendly at scale, and integrates smoothly with backend paging APIs.
