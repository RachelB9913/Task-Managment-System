# **Task Management System with AWS Cognito and Role-Based Access**

## **Overview**
This is a backend system for managing **users, projects, and tasks**, built with **Java Spring Boot**.  
The system supports **user authentication and authorization** using **AWS Cognito** and provides **RESTful APIs** for CRUD operations on projects and tasks.  
It also includes pagination, logging, and role-based access control for scalability and security.

---

## **Features**
- **User Authentication & Authorization**
  - AWS Cognito for secure identity management.
  - Role-based access control (`USER`, `ADMIN`).
- **Project Management**
  - Create, read, update, delete projects.
  - View paginated project lists.
- **Task Management**
  - Create, read, update, delete tasks.
  - View tasks per project with summaries.
- **Security**
  - JWT-based authentication.
  - Restricted access based on user roles.
- **Persistence**
  - File-based H2 database for development/testing.
- **Logging**
  - Detailed request and DB state logging for debugging.

---

## **Technology Stack**
- **Backend**: Java 21, Spring Boot 3
- **Security**: AWS Cognito (OAuth2 Resource Server, JWT)
- **Database**: H2 (file-based, easy migration to PostgreSQL/MySQL)
- **Build Tool**: Maven
- **Testing**: JUnit 5, Mockito

## **Configuration**
Update `src/main/resources/application.properties` with your AWS Cognito details:

```properties
spring.application.name=taskManagement
spring.security.oauth2.resourceserver.jwt.issuer-uri=https://cognito-idp.<region>.amazonaws.com/<userPoolId>

cognito.client-id=<your-client-id>
cognito.redirect-uri=http://localhost:8080/auth/callback
cognito.token-uri=https://<your-domain>.auth.<region>.amazoncognito.com/oauth2/token
aws.region=<your-region>
```

## **Running the Project**
1. **Clone the repository**
   ```bash
   git clone https://github.com/RachelB9913/Task-Managment-System.git
   cd taskManagement
   ```

2. **Build the project**
   ```bash
   ./mvnw clean install
   ```

3. **Run the application**
   ```bash
   ./mvnw spring-boot:run
   ```

4. **Access the API**
   - Base URL: `http://localhost:8080`
   - Use AWS Cognito credentials to authenticate and obtain a JWT.

## **API Endpoints**

### **Authentication**
| Method | Endpoint     | Description |
|--------|--------------|-------------|
| GET    | `/users/me`  | Get logged-in user info |

### **Projects**
| Method | Endpoint                  | Description |
|--------|---------------------------|-------------|
| GET    | `/projects/me`            | Get to see all user's projects |
| GET    | `/projects/{id}`          | Get project {id}'s details |
| POST   | `/projects`               | Create a project |
| PUT    | `/projects/{id}`          | Update a project |
| DELETE | `/projects/{id}`          | Delete a project |

### **Tasks**
| Method | Endpoint                                      | Description |
|--------|-----------------------------------------------|-------------|
| GET    | `/projects/{projectId}/tasks`                 | Get all tasks of project {id} |
| GET    | `/projects/{projectId}/tasks/{taskId}`        | Get a task by ID |
| POST   | `/projects/{projectId}/tasks`                 | Create a task in a project |
| PUT    | `/projects/{projectId}/tasks/{taskId}`        | Update a task |
| DELETE | `/projects/{projectId}/tasks/{taskId}`        | Delete a task |

### **Admin - Extra**
| Method | Endpoint                                      | Description |
|--------|-----------------------------------------------|-------------|
| GET    | `/admin/projects/all`                         | Get all projects of all users |
| GET    | `/admin/tasks/all`                            | Get all tasks of all users |
| GET    | `/admin/users/all`                            | Get all info of all users |
| PUT    | `/admin/users/{sub}`                          | get info of a specific user | 
| DELETE | `/admin/users/{sub}`                          | Delete a specific user | - started implementing
| PUT    | `/admin/users/{sub}/role/{newRole}`           | change user's group (ADMIN/ USER) | - started implementing

## **How to Use Postman for API Testing**

You can use Postman to test the API endpoints. Follow these steps:

1. **Start the Backend**
   - Make sure the application is running locally at `http://localhost:8080`.

2. **Authenticate via AWS Cognito**
   - Open the following URL in your browser:
     ```
     https://eu-north-1lbrgh68wz.auth.eu-north-1.amazoncognito.com/login?client_id=3tj5gt4kglobd8n7r3cqrb5in5&response_type=code&scope=email+openid+profile&redirect_uri=http%3A%2F%2Flocalhost%3A8080%2Fauth%2Fcallback
     ```
   - Log in or sign up as a new user.
   - After login, you will be redirected to `http://localhost:8080/auth/callback`.
   - The backend will handle the authentication and obtain a JWT token for you.

3. **Obtain the JWT Token**
   - To use Postman, you need a valid JWT token.
   - The app will surface tokens in two places:
    * Backend logs (look for the printed token values after successful login).
    * The redirect page at /auth/callback (it displays the tokens).
   - Copy the id_token and use it in your requests.

4. **Set Up Postman Requests**
   - Set the request method (GET, POST, PUT, DELETE) and the endpoint URL (e.g., `http://localhost:8080/projects`).
   - In the **Headers** tab, add:
     - `Authorization: Bearer <JWT_TOKEN>`
   - For POST/PUT requests, set the body to raw JSON and select `application/json` as the content type.

5. **Example Request**
   - **Get all projects for the logged-in user:**
     - Method: `GET`
     - URL: `http://localhost:8080/api/projects/me`
     - Headers:
       - `Authorization: Bearer <JWT_TOKEN>`
   - **if there isn't still project:**
     - Method: `POST`
     - URL: `http://localhost:8080/api/projects`
     - Headers:
       - `Authorization: Bearer <JWT_TOKEN>`
     - Body:
       - { 
           "name": "Fitness Tracker", 
           "description": "Track workouts and goals" 
         }


6. **Tip:**
   - You can export a Postman collection with all endpoints and import it into Postman for easier testing.

**Note:** The JWT token is required for all protected endpoints. If you encounter authentication errors, ensure your token is valid and not expired.
