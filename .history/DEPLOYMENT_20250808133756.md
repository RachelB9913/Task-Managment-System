# Deployment Strategy

This document outlines how I would deploy this full-stack application to production in a way that supports scalability, performance, and reliability. The system is expected to handle around 10,000 daily active users and includes both a client-side (React) and server-side (Spring Boot) application. 


## Overview

- **Backend:** Spring Boot application using RESTful APIs
- **Frontend:** React-based client-side application
- **Authentication:** AWS Cognito for secure identity management
- **Database:** Currently using H2 (file-based) — planned to migrate to PostgreSQL


## Current limitations:
Before outlining the deployment strategy, it’s important to highlight some of the challenges that would arise from deploying the current state of the application as-is:

1. Currently, my app runs on a single Spring Boot instance with an embedded H2 DB. 
- > This is not scalable or fault-tolerant. Memory and CPU limits will break under load.
- > Not suited for concurrent access or real-world persistence.
- > Risk of data loss or corruption.
2. No load balancing
- > When 10k users hit endpoints at once (e.g. login, create tasks), I will get bottlenecks without scaling.
3. No caching
- > Every request (e.g. GET /users/me) hits the DB. This slows performance under load.
- > Frequent identical requests (e.g., profile data) will unnecessarily hit the database.
4. No CI/CD pipeline. Manual deployment is not sustainable or safe for production.


## Here is my suggestion:

### Backend (Spring Boot)
- Use Docker - so it could run anywhere with everything needed inside
- Run the app on the cloud without managing any servers 
- If lots of users are using the app, to run more copies of it (scale out). If usage decreases, to scale it back down.
- spread incoming requests across all running instances so no server is overwhelmed.

### Frontend (React)
- Build the app using `npm run build`
- also to put into a cloud storage - that way it will load fast (no matter where the user is)
- The server should use the react app globaly and correctly connected to the backend


### DataBase
- Use **PostgreSQL via Amazon RDS** for a reliable, persistent relational data store
- Apply proper indexing and normalization
- save daily backups and recovery points

### Load Balancer
- Handle incoming requests efficiently
- Spread load between instances
- In case of instance failure provide health checks to reroute traffic 

### Caching
- Cache common queries (user info, project/task lists)
- Will help reduce DB load
- Improves API response time (and by that also user experience)

### Security & Authentication
- Use **JWT validation** on the backend for each request
- Protect sensitive config (DB passwords, secrets)
- Use the **role-based access control** to restrict actions by user type
- Use **CORS configuration** to control cross-origin access between frontend and backend
- Use HTTPS for encrypted communication between client and server
