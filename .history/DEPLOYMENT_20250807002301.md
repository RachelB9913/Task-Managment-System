# Deployment Strategy

This document outlines how I would deploy this full-stack application to production in a way that supports scalability, performance, and reliability. The system is expected to handle around 10,000 daily active users and includes both a client-side (React) and server-side (Spring Boot) application. 


### Here is my suggestion:

## Overiew

- **Backend:** Spring Boot application using RESTful APIs
- **Frontend:** React-based client-side application
- **Authentication:** AWS Cognito for secure identity management
- **Database:** Currently using H2 (in-memory or file-based) — planned to migrate to PostgreSQL


## Current limitations:
Before outlining the deployment strategy, it’s important to highlight some of the challenges that would arise from deploying the current state of the application as-is:

1. Currently, my app runs on a single Spring Boot instance with an embedded H2 DB. 
  -> This is not scalable or fault-tolerant. Memory and CPU limits will break under load.
  -> Not suited for concurrent access or real-world persistence.
  -> Risk of data loss or corruption.
2. No load balancing
  -> When 10k users hit endpoints at once (e.g. login, create tasks), I will get bottlenecks without scaling.
3. No caching
  -> Every request (e.g. GET /users/me) hits the DB. This slows performance under load.
  -> Frequent identical requests (e.g., profile data) will unnecessarily hit the database.
4. No CI/CD pipeline. Manual deployment is not sustainable or safe for production.
